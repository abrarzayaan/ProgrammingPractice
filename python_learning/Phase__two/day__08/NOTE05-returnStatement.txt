return বোঝার আগে প্রোগ্রামিংয়ের ৩টি মৌলিক সত্তা—Variable, Parameter, এবং Argument-এর ভেতরের পার্থক্য মেমরি লেভেলে পরিষ্কার করা প্রয়োজন। 
এই তিনটির সম্পর্ক স্পষ্ট হলে return-এর রহস্য পানির মতো পরিষ্কার হয়ে যায়।

১. Variable, Parameter ও Argument: মেমরি লেভেলে পার্থক্য
কোড যখন রান হয়, এই তিনটি উপাদান মেমরিতে কীভাবে কাজ করে তা একটি উদাহরণ দিয়ে দেখা যাক:

__code__(01):
{
    # ১. Parameter: 'x' এবং 'y' হলো ফাংশনের ফর্মাল প্যারামিটার
    def add(x, y):
        result = x + y   # result হলো Local Variable
        return result

    # ২. Variable: গ্লোবাল মেমরিতে 'a' একটি ভ্যারিয়েবল
    a = 10               

    # ৩. Argument: 'a' এবং ২০ হলো আর্গুমেন্ট
    output = add(a, 20)

__code vitualization__
[ Heap Memory ]
(10)  <--- Object
(20)  <--- Object

[ Global Scope ]
a --------> পয়েন্ট করছে (10) কে

[ add() Stack Frame ]
x --------> পয়েন্ট করছে (10) কে  (Parameter receives Argument 'a')
y --------> পয়েন্ট করছে (20) কে  (Parameter receives literal 20)
result ---> পয়েন্ট করছে (30) কে  (Local Variable)

}

Variable:
 > আসলে এটি কী?
    মেমরির কোনো অবজেক্টকে চেনার জন্য দেওয়া একটি নাম (Identifier)।
 > মেমরিতে এর কাজ:
    মেমরির হিপে থাকা কোনো ডেটার মেমরি অ্যাড্রেস ধরে রাখা।

Parameter:
 > আসলে এটি কী?
    ফাংশন ডিফাইন করার সময় ব্র্যাকেটে লেখা ফাঁকা স্লট বা প্লেসহোল্ডার (x, y)।
 > মেমরিতে এর কাজ:
    এটি কেবল ফাংশনের নিজস্ব লোকাল স্ট্যাক ফ্রেমে তৈরি হওয়া একটি লোকাল ভ্যারিয়েবল, যা বাইরে থেকে মান পাওয়ার অপেক্ষায় থাকে।

Argument:
 > আসলে এটি কী?
    ফাংশন কল করার সময় ব্র্যাকেটের ভেতর পাঠানো আসল মান বা রেফারেন্স (a, 20)।
 > মেমরিতে এর কাজ
    এটি সেই আসল অবজেক্ট বা ডেটা, যার মেমরি অ্যাড্রেস ফাংশন কলের সময় প্যারামিটারের স্লটে কপি করে দেওয়া হয়।


২. return আসলে কী এবং কেন এর আবিষ্কার?
কেন আবিষ্কার হলো?
ফাংশনের একটি স্ট্যাক ফ্রেম থাকে। ফাংশন যখন রান করে, সে নিজের ভেতরে যত লোকাল ভ্যারিয়েবল বানায় (যেমন উপরের result), 
ফাংশনের কাজ শেষ হওয়ার সাথে সাথে স্ট্যাক ফ্রেম ধ্বংস হয়ে যায় এবং সেই সব লোকাল ভ্যারিয়েবল চিরতরে মুছে যায়।

তাহলে ফাংশন ভেতরে যে কষ্ট করে হিসাব করল, সেই ফলাফল বাইরের দুনিয়া পাবে কীভাবে?
এই ডেটা হারানোর সমস্যা সমাধানের জন্যই জন্ম হলো return-এর।

return মেমরিতে ঠিক কী করে?
return স্টেটমেন্টের দুটি কাজ:
 1. হ্যান্ডওভার (Handover): return-এর ডানপাশে থাকা এক্সপ্রেশনের মেমরি অ্যাড্রেসটি সে কলারের (যেখান থেকে কল করা হয়েছিল) হাতে তুলে দেয়।
 2. তাৎক্ষণিক সমাপ্তি (Immediate Termination): ফাংশনের নিচে আরও ১০০ লাইনের কোড থাকলেও সেদিকে তাকায় না; সাথে সাথে স্ট্যাক ফ্রেম ভেঙে কলারের লাইনে ফেরত চলে আসে।



৩. তোমার ৪টি প্রধান কনফিউশনের ব্যবচ্ছেদ
কনফিউশন ১: "প্যারামিটারকে কীভাবে রিটার্ন করা যায়?" (return x)

__code__(02):
{
   def identity(x):
    return x

   num = 50
   final = identity(num)
}

মেমরিতে কী ঘটছে:

1. num ভ্যারিয়েবলটি মেমরির 50 অবজেক্টকে পয়েন্ট করছিল।
2. যখন identity(num) কল করা হলো, প্যারামিটার x-কেও সেই একই 50 অবজেক্টের অ্যাড্রেস দেওয়া হলো।
3. return x বলা মানে হলো: "এই x যার মেমরি অ্যাড্রেস ধরে আছে, সেই অ্যাড্রেসটাই কলারের কাছে ফেরত পাঠিয়ে দাও।"
4. কলার সেই অ্যাড্রেসটি নিয়ে final ভ্যারিয়েবলে বসিয়ে দিল। এখানে কোনো নতুন অবজেক্ট তৈরি হয়নি; কেবল একটি মেমরি রেফারেন্স ভেতর দিয়ে গিয়ে আবার বাইরে ফেরত আসল।


কনফিউশন ২: "রিটার্নে প্রিন্ট কেন করা যায়?" (return print(...))
অনেকেই ভুল করে এই কোড লেখেন:

__code__(03):
{
   def say_hello():
    return print("Hello World")

   res = say_hello()
   print(res)
}

আউটপুট দেখলে চমকে যেতে পারো:
__code_output__(03):
{
   Hello World
   None
}

কেন এমন হলো? (Screen Output বনাম Memory Return)

 > print() একটি ফাংশন: এর একমাত্র কাজ হলো মনিটরের টার্মিনালে কিছু পিক্সেল দেখানো। কিন্তু পাইথনে প্রতিটি ফাংশনকেই কাজ শেষে কিছু না কিছু মেমরিতে ফেরত দিতে হয়। 
   print() স্ক্রিনে লেখা দেখানোর পর নিজে মেমরিতে রিটার্ন করে None।

 > যখন তুমি লেখো return print("Hello World"):
  - পাইথন আগে ব্র্যাকেটের ভেতরের অংশ রান করে: print("Hello World") এক্সিকিউট হয়ে স্ক্রিনে লেখা চলে আসে।
  - print তার কাজ শেষ করে পাইথনকে দেয় None।
  - লাইনটি তখন পরিণত হয়: return None-এ!
  - ফলে res ভ্যারিয়েবলটির ভেতর মেমরি থেকে জমা হয় None।

গোল্ডেন রুল: print মনিটরে মানুষের চোখের জন্য আউটপুট দেখায়, কিন্তু কোডের কোনো ভ্যারিয়েবলকে ডেটা দিতে পারে না। ডেটা পাস করার একমাত্র উপায় হলো return।
