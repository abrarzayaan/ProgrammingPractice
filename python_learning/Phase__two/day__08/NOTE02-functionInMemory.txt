কল স্ট্যাক (Call Stack) কীভাবে কোডের মেমরি জাম্প সামলায়, তা স্টেপ-বাই-স্টেপ দেখার আগে ৩টি হার্ডওয়্যার কনসেপ্ট পরিষ্কার থাকা দরকার। এগুলো ছাড়া কল স্ট্যাকের আসল জাদু বোঝা যায় না।

১. যা আগে বোঝা দরকার (Prerequisites)

কম্পিউটারের প্রসেসর (CPU) যখন কোনো কোড চালায়, তখন সে অন্ধের মতো ৩টি জিনিস ট্র্যাক করে:
 1. Instruction Pointer বা Program Counter (IP / PC):
    > এটি CPU-এর ভেতরের একটি অতি দ্রুত মেমরি (রেজিস্টার)।
    > এর কাজ একটাই: "পরের মুহূর্তে মেমরির কোন লাইনের ইনস্ট্রাকশন চালাব, সেই মেমরি অ্যাড্রেস মনে রাখা।" প্রতিটা লাইন চালানোর সাথে সাথে এটি নিজে থেকেই পরবর্তী লাইনে এগিয়ে যায়।

 2. Stack Pointer (SP):
    > এটি আরেকটি রেজিস্টার, যা নির্দেশ করে স্ট্যাক মেমরির ঠিক কোন লেভেলে আমরা এখন আছি।

 3. Stack Frame (বা Activation Record):
    যখনই কোনো ফাংশন কল হয়, মেমরির স্ট্যাক অংশে সেই ফাংশনটির জন্য একটা ছোট "ব্যক্তিগত বাক্স" বা ব্লক বরাদ্দ করা হয়। এর ভেতর থাকে:
     > Return Address: কাজ শেষে CPU কোন লাইনে ফিরে যাবে।
     > Parameters / Arguments: ফাংশনে কী মান পাঠানো হলো।
     > Local Variables: ফাংশনের নিজস্ব ভ্যারিয়েবল।
স্ট্যাক কাজ করে LIFO (Last In, First Out) নিয়মে—অর্থাৎ সবার শেষে যে ফাংশনটি ঢুকবে, তার কাজ সবার আগে শেষ হবে এবং সে সবার আগে মেমরি থেকে বের হয়ে যাবে।


২. একটি বাস্তব কোড দৃশ্যপট
ধরা যাক আমাদের কাছে নিচের সাধারণ কোডটি আছে:

__code__(01):
{
    # লাইন ১০০:
    def calc_tax(income):
        rate = 0.10             # লাইন ১০১
        return income * rate    # লাইন ১০২

    # লাইন ২০০:
    def process_salary(base):
        bonus = 500             # লাইন ২০১
        total = base + bonus    # লাইন ২০২
        tax = calc_tax(total)   # লাইন ২০৩ (এখানে Nested Function Call হচ্ছে)
        net = total - tax       # লাইন ২০৪ (ট্যাক্স হিসাব শেষে এখানে ফিরতে হবে)
        return net              # লাইন ২০৫

    # লাইন ৩০০ (Main Program):
    final = process_salary(5000) # লাইন ৩০১
    print(final)                 # লাইন ৩০২ (স্যালারি হিসাব শেষে এখানে ফিরতে হবে)
}
এখন দেখা যাক CPU এবং Call Stack ধাপে ধাপে কীভাবে মেমরি জাম্প নিয়ন্ত্রণ করে।


৩. Step-by-Step Memory Trace
ধাপ ১: মেইন প্রোগ্রাম শুরু (Main Scope)
 > IP (Instruction Pointer): লাইন ৩০১ নির্দেশ করছে।
 > স্ট্যাকের অবস্থা: স্ট্যাকে শুধু মেইন প্রোগ্রামের বেসিক ফ্রেম বিদ্যমান।

    {
        [ Call Stack ]
        +-------------------------+
        | Frame: <Main>           |
        |  - IP: Line 301         |
        +-------------------------+
    }

ধাপ ২: process_salary(5000) কল হলো
CPU যখন লাইন ৩০১-এ দেখল একটি ফাংশন কল করতে হবে, তখন হার্ডওয়্যারে কল মেকানিজম ট্রিগার হয়:
 > Return Address সংরক্ষণ: CPU মনে রাখে, "এই ফাংশনের কাজ শেষ হলে আমাকে লাইন ৩০২-এ ফিরতে হবে।" এই ঠিকানাটি সে স্ট্যাকে লিখে রাখে।
 > Frame পুশ: process_salary-র জন্য স্ট্যাকে একটি নতুন ফ্রেম তৈরি হয়।
 > IP জাম্প: CPU তার Instruction Pointer সরাসরি লাইন ২০১-এ পাঠিয়ে দেয়।

    {
        [ Call Stack ]
        +------------------------------------+
        | Frame: process_salary              |  <-- Stack Pointer (SP) এখন এখানে
        |  - Return Address: Line 302        |
        |  - Param: base = 5000              |
        |  - Locals: bonus = 500, total = 5500|
        +------------------------------------+
        | Frame: <Main>                      |
        |  (অপেক্ষা করছে লাইন ৩০২ এর জন্য)   |
        +------------------------------------+
    }


ধাপ ৩: নেস্টেড কল—calc_tax(total)
লাইন ২০৩-এ এসে CPU দেখল আরেকটি ফাংশন কল করতে হবে (calc_tax)। এখন কিন্তু process_salary নিজেই শেষ হয়নি!

CPU একই কাজ আবার করে:

 > Return Address সংরক্ষণ: CPU এবার স্ট্যাকে লিখে রাখে: "এই ট্যাক্স হিসাব শেষ হলে আমাকে process_salary-র লাইন ২০৪-এ ফিরতে হবে।"
 > নতুন Frame পুশ: calc_tax-এর জন্য আরেকটি ছোট ফ্রেম স্ট্যাকের শীর্ষে বসে।
 > IP জাম্প: CPU তার পয়েন্টার লাইন ১০১-এ পাঠিয়ে দেয়।

    {
        [ Call Stack ]
        +------------------------------------+
        | Frame: calc_tax                    |  <-- SP এখন শীর্ষে
        |  - Return Address: Line 204        |
        |  - Param: income = 5500            |
        |  - Local: rate = 0.10              |
        +------------------------------------+
        | Frame: process_salary              |
        |  (পজ হয়ে আছে লাইন ২০৩ তে)         |
        +------------------------------------+
        | Frame: <Main>                      |
        +------------------------------------+
    }

ধাপ ৪: calc_tax এর কাজ শেষ এবং মেমরি পপ (RET)
লাইন ১০২-এ এসে calc_tax হিসাব করল: $5500 \times 0.10 = 550$।
এখনই ফাংশনের জাদুকরী মুহূর্ত ঘটে:
 > রিটার্ন ভ্যালু হ্যান্ডওভার: রিটার্ন ভ্যালু 550-কে CPU একটি বিশেষ রেজিস্টারে (যেমন x86 আর্কিটেকচারে RAX/EAX) রেখে দেয়।
 > Return Address রিড: CPU স্ট্যাক ফ্রেম থেকে পড়ে নেয়: "কোথায় ফিরতে হবে? লাইন ২০৪-এ।"
 > Frame ধ্বংস (Pop): calc_tax-এর পুরো ফ্রেম স্ট্যাক থেকে মুছে ফেলা হয়। এর ভেতরের rate ভ্যারিয়েবল পুরোপুরি ধ্বংস হয়ে যায়।
 > IP জাম্প: CPU তার Instruction Pointer সেট করে লাইন ২০৪-এ।

    {
        [ Call Stack ]
        (calc_tax ফ্রেম ধ্বংস হয়ে গেছে!)
        +------------------------------------+
        | Frame: process_salary              |  <-- SP আবার এখানে নেমে আসলো
        |  - Return Value গ্রহণ করলো: 550    |
        |  - tax = 550                       |
        |  - net = 5500 - 550 = 4950         |
        +------------------------------------+
        | Frame: <Main>                      |
        +------------------------------------+
    }


ধাপ ৫: process_salary এর কাজ শেষ
লাইন ২০৫-এ এসে process_salary তার হিসাব করা net ($4950$) রিটার্ন করে।
 > CPU রিটার্ন ভ্যালু 4950 রেজিস্টারে রাখে।
 > সে তার ফ্রেমে দেখে Return Address লেখা আছে: লাইন ৩০২।
 > process_salary-র ফ্রেম স্ট্যাক থেকে মুছে যায় (base, bonus, total মেমরি থেকে বিলীন)।
 > CPU লাইন ৩০২-এ ফিরে আসে এবং প্রিন্ট করে 4950। স্ট্যাক আবার সম্পূর্ণ খালি হয়ে মেইন স্টেটে ফিরে আসে।


৪. কেন এই মেকানিজমটি প্রোগ্রামিং দুনিয়াকে বদলে দিয়েছিল?
 - কোনো ভ্যারিয়েবল সংঘাত নেই: process_salary-র ভেতরে যদি কোনো ভ্যারিয়েবল থাকত যার নাম rate, আর calc_tax-এর ভেতরেও rate, 
 কোনো সমস্যা হতো না। কারণ দুটি আলাদা ফ্রেমে (আলাদা মেমরি অ্যাড্রেসে) বাস করে।

 - Recursion (পুনরাবৃত্তি) সম্ভব হওয়া: একটি ফাংশন যখন নিজেকেই আবার কল করে, তখন স্ট্যাকে একই ফাংশনের একাধিক ফ্রেম একের ওপর এক জমতে থাকে। 
 প্রত্যেকে নিজের ইনপুট এবং রিটার্ন অ্যাড্রেস আলাদাভাবে মনে রাখে।

 - Stack Overflow-এর কারণ: যদি কোনো ফাংশন এমনভাবে কল হতে থাকে যার কোনো শেষ নেই (Infinite Recursion), তখন ফ্রেম জমতে জমতে স্ট্যাকের জন্য বরাদ্দকৃত মেমরি উপচে পড়ে। 
 তখনই অপারেটিং সিস্টেম প্রোগ্রামটিকে মেরে ফেলে এবং এর নাম দেয় Stack Overflow।
